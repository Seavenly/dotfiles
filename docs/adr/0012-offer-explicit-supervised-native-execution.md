# Offer explicit supervised native execution

Provide a separate Linux supervised native execution contract for a cooperative
operator using the official CLIs' permission controls. ADR-0011's strict route
continues to reject unproved startup and permission enforcement. Waiting for
independent enforcement would otherwise prevent a useful supervised first run.

The owner and each prepare/launch request must explicitly select the supervised
contract. Exact execution descriptions and the immutable preparation confirmation
name requested CLI permissions, trusted ambient startup, and the absence of
independent workspace and tool-network enforcement. A supervised result never
qualifies the strict route or rewrites historical qualification evidence.

RunAuthority, exact workspace claims, bounded attempts, Linux process retirement,
conservative recovery, registered verification, candidate sealing and independent
review retain their existing contracts. The initial route permits feature
verify/test and local review only. It grants no publication, remote mutation,
normal-use rollout, global permission change or default cutover.

Explicit supervised local requests may target an existing clean repository;
disposable repositories are the first-trial procedure rather than a permanent
admission restriction. One reusable private owner per repository retains its
workspace authority across requests. Content verification reports Git-backed
observations and independent model critique, while behavioral test execution
requires the registered pinned health/expected-RED/GREEN contract. Preparation
confirmation and retained status state that distinction.
